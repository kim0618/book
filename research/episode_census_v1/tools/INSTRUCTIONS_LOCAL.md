# 로컬 단계 추가 지침 (INSTRUCTIONS.md에 덧붙임)

로컬 묶음(L01~L34)은 사용자의 PC에서 실행한 코딩 도구 세션 기록이다. 기본 지침(INSTRUCTIONS.md)을 모두 따르고, 아래를 추가로 지킨다.

## 입력의 특징
- 발언자: U=사용자(또는 도구가 사용자 역할로 주입한 지시문), CC=Claude Code, CX=Codex, S=시스템.
- 한 구간 = 한 세션이다. 긴 세션은 여러 사건을 담을 수 있고, 짧은 세션(하위 에이전트, 자동 실행)은 큰 작업의 일부일 수 있다.
- CC/CX의 중간 메시지는 90자로 잘려 있다("~하겠습니다" 같은 진행 문장). 사용자 메시지 직전·세션 끝의 보고 메시지가 더 길게 남아 있다.
- 사용자 메시지에 ChatGPT가 작성한 지시문·프롬프트를 붙여넣은 경우가 많다. 이것이 "ChatGPT 제안 → 사용자가 Claude Code·Codex에 전달 → 결과 보고 → 사용자가 다시 ChatGPT에 확인"하는 연결 구조의 근거다. 붙여넣은 글의 작성자가 원문으로 확인될 때만 "사용자가 붙여넣은 ChatGPT 지시"라고 쓰고, 아니면 "사용자가 붙여넣은 지시문(작성자 확인 불가)"이라고 쓴다.
- 사용자 역할로 들어온 자동 주입(시스템 알림, 하위 에이전트 프롬프트, 예약 실행 문구 등)은 사용자의 실제 발언으로 서술하지 않는다. 사용자 반응 인용(sp=U)으로 고를 때는 실제 사람이 쓴 문장인지 확인한다.

## 같은 묶음 안의 통합
- 같은 작업을 이어서 하는 여러 세션(예: 같은 단계 번호, 같은 오류, 이전 세션 보고를 이어받음)은 한 에피소드로 묶는다.
- 하위 에이전트·자동 반복 세션처럼 그 자체로 사건이 아닌 구간은 관련 에피소드에 통합하거나, 관련 사건이 없으면 PRESERVE(라벨에 "자동 실행" 등)로 둔다.

## 웹 에피소드와의 연결
- 묶음별 연결 후보 파일 `chunks/<묶음>_links.md`가 있다. 기존 CROSS_LINKS(같은 문장 공유)로 찾은 웹 구간과 그 구간이 속한 웹 에피소드 key가 적혀 있다.
- 실제로 같은 사건의 앞뒤 단계(예: ChatGPT가 쓴 지시문을 사용자가 이 세션에 붙여넣음, 이 세션의 보고를 사용자가 ChatGPT에 붙여넣음)라고 원문으로 확인되면 links에 `{"hint":"웹 에피소드 Wxx-yy와 같은 사건(…단계)", "basis":"로컬 E#### #n ↔ 웹 E####", "status":"확정"}`으로 적고, 추가로 `"web_episode":"Wxx-yy"` 키를 넣는다.
- 공유 문장이 일반 문구뿐이거나 순서가 맞지 않는 등 증거가 부족하면 `"status":"미확정"`으로 둔다. 문장 공유만으로 확정하지 않는다.

## 이 책 프로젝트 자체에 관한 세션
- 2026-10월 후반에는 이 책을 만드는 작업(원고 작성, 대화 수집, 목차, 감사) 세션이 있다. 이것도 사건으로 기록하되 프로젝트 코드는 BOOK으로 쓴다. 과거 원고의 내용은 요약하지 않는다.
- "확정"은 웹 원문에서 ChatGPT가 지시문을 준 메시지 또는 사용자가 이 세션 보고를 붙여넣은 메시지를 직접 확인했을 때만 쓴다(웹 축약본 `chunks/Wxx.md` 또는 `parsed.json`에서 확인 가능). basis에 양쪽 구간·메시지 번호를 적는다. 문장 공유·시각 순서만으로는 "미확정".
